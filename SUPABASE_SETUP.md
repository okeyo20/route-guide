# RouteGuide Supabase setup

## 1. Create the project

1. Open https://supabase.com and create a project.
2. In **Authentication > Providers**, enable **Email**.
3. Optionally enable **Google** after configuring OAuth credentials.
4. In **Project Settings > API**, copy the project URL and the public anon/publishable key.
5. Put those two public values in `supabase-config.js`.
6. If using the Google Identity Services button, put your Google Web Client ID
    in the `googleClientId` field in `supabase-config.js`.

For Google login, also add the deployed site URL and these callback URLs under
**Authentication > URL Configuration > Redirect URLs**:

```text
https://soft-bunny-c09fc7.netlify.app/index.html
https://soft-bunny-c09fc7.netlify.app/register.html
https://soft-bunny-c09fc7.netlify.app/admin.html
http://localhost:5500/index.html
http://localhost:5500/register.html
http://localhost:5500/admin.html
http://127.0.0.1:5500/index.html
http://127.0.0.1:5500/register.html
http://127.0.0.1:5500/admin.html
```

Under **Authentication > Providers**, enable the social providers you want to
offer: Google, GitHub and/or Facebook. Add each provider's client ID and secret
from its developer console, then add the Supabase OAuth callback URL shown on
the provider screen to that provider's OAuth application. Social login returns
the user to the page that started login, then RouteGuide opens the dashboard.

Use this callback URL for each provider:

```text
https://pcupcqhbjwbjhvkdddyl.supabase.co/auth/v1/callback
```

Provider setup:

1. **Google:** Google Cloud Console > APIs & Services > Credentials > OAuth client ID > Web application.
2. **GitHub:** GitHub Settings > Developer settings > OAuth Apps > New OAuth App. Use the callback URL as the Authorization callback URL.
3. **Facebook:** Meta for Developers > My Apps > Facebook Login > Settings. Add the callback URL to Valid OAuth Redirect URIs.

Copy each provider's Client ID and Client Secret directly into its Supabase
provider settings. Do not put provider secrets in HTML or JavaScript.

The website also blocks an email address for 15 minutes after five failed
password attempts. Supabase remains the authoritative authentication service
and should keep its own authentication rate limits enabled.

Do not put the service-role key in this website. It must remain server-side.

## 2. Create an admin user

In Supabase, open **Authentication > Users** and create the admin account using your email. The password-reset email will be sent by Supabase.

The frontend must also restrict admin access by email or, preferably, by a database role. A login alone is not enough to authorize administrative actions.

## 3. Create data tables

Run this SQL in the Supabase SQL editor:

```sql
create table public.route_fares (
    id bigint generated by default as identity primary key,
    route text not null unique,
    fare_ksh numeric not null check (fare_ksh >= 0),
    source text,
    checked_on date not null default current_date,
    updated_at timestamptz not null default now()
);

create table public.fuel_prices (
    id bigint generated by default as identity primary key,
    petrol_ksh numeric not null check (petrol_ksh >= 0),
    diesel_ksh numeric not null check (diesel_ksh >= 0),
    effective_on date not null,
    updated_at timestamptz not null default now()
);

alter table public.route_fares enable row level security;
alter table public.fuel_prices enable row level security;

create policy "Anyone can read route fares"
on public.route_fares for select using (true);

create policy "Anyone can read fuel prices"
on public.fuel_prices for select using (true);
```

## Anonymous community comments

Run this SQL to enable shared comments on the About page. Each browser receives
an anonymous RouteGuide passport; no name, email or login is required.

```sql
create table public.routeguide_comments (
    id bigint generated by default as identity primary key,
    passport text,
    display_name text,
    is_anonymous boolean not null default true,
    comment text not null check (char_length(comment) between 1 and 500),
    created_at timestamptz not null default now()
);

-- If routeguide_comments already exists from the earlier setup, run this instead:
alter table public.routeguide_comments add column if not exists display_name text;
alter table public.routeguide_comments add column if not exists is_anonymous boolean not null default true;

alter table public.routeguide_comments enable row level security;

create policy "Anyone can read RouteGuide comments"
on public.routeguide_comments for select using (true);

create policy "Anyone can post RouteGuide comments"
on public.routeguide_comments for insert with check (
    char_length(comment) between 1 and 500
    and (is_anonymous = true or char_length(display_name) between 1 and 60)
);
```

For shared public posts and images, also run:

```sql
create table public.traffic_reports (
    id bigint generated by default as identity primary key,
    road text not null,
    type text not null,
    note text,
    image_url text,
    created_at timestamptz not null default now(),
    expires_at timestamptz
);

alter table public.traffic_reports enable row level security;

create policy "Anyone can read traffic reports"
on public.traffic_reports for select using (true);

create policy "Anyone can publish traffic reports"
on public.traffic_reports for insert with check (true);

-- Replace this with an auth.uid() admin check before production.
create policy "Admins can delete traffic reports"
on public.traffic_reports for delete using (auth.uid() is not null);
```

Create a public Storage bucket named `community-images`. Add a Storage insert policy for authenticated or anonymous users according to your moderation policy. Public posting should eventually include rate limits, report abuse controls and image moderation.

For production updates, add an `admins` table and write policies that allow insert/update only when `auth.uid()` belongs to an approved admin. Do not use an open update policy.

## 4. Email redirects

In **Authentication > URL Configuration**, add the deployed website URL and the password-reset page URL. Test the reset flow from the deployed domain, not only from a local `file://` page.

## 5. Local development

A local web server is required for authentication redirects and module loading. Use VS Code Live Server or run:

```powershell
py -m http.server 5500
```

Then open `http://localhost:5500/admin.html`.
